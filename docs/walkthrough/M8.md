# M8 walkthrough: packaging, infrastructure and docs

## What was built
The project can now run in three ways. `pnpm dev` starts the API and the web app on your machine. `docker compose up --build` builds two production images and starts them with a local placeholder API key. `sst.config.ts` describes an AWS deployment (the API as one Fargate container behind a load balancer, the web app on CloudFront and Lambda), ready for the owner to deploy with the commands in `docs/DEPLOY.md`; nothing was deployed. The repository also got its public face: README (with examples whose output was pasted from real runs), ARCHITECTURE, DEPLOY, CONTRIBUTING, SECURITY and CHANGELOG.

## Design decisions
1. **A container, not a Lambda, for the API.** SST builds functions with esbuild, which drops the decorator metadata NestJS needs to wire its classes together. A container runs the normal Nest build, so production behaves like the tests.
2. **`pnpm deploy` for production-only images.** Each Dockerfile builds the whole workspace once, then `pnpm deploy --prod` copies one app with only its production dependencies, with core included as a real package. The image runs as the `node` user, and a health check uses Node's own `fetch` because the slim image has no curl.
3. **The infrastructure is type-checked like code.** `pnpm typecheck` runs `sst install` and checks `sst.config.ts` and `infra/`, so a wrong option name fails in CI instead of during a deploy.
