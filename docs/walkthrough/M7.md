# M7 walkthrough: the web app

## What was built
`apps/web` is a Next.js app on port 3010. `/` validates a rooming list (tiles, a filterable issues table, a nights table) and converts a valid one into a download. `/compare` shows who was added, removed or changed between two versions. `/formats` lists each export target with its options and what is verified or assumed. The browser only talks to Next.js: four route handlers under `/api/*` forward to the API with the API key, which never leaves the server.

## Design decisions
1. **A bounded proxy.** `src/lib/proxy.ts` refuses an upload with no `Content-Length`, or over 5 MB per file plus 1 MB, before reading it. Only allow-listed headers come back; an unreachable API becomes a 502 `API_UNAVAILABLE` problem.
2. **The UI follows the API.** Option inputs are generated from each target's JSON Schema, and types come from core (`import type` only, so no core code ships to the browser).
3. **Server-only by test.** A unit test fails if any `"use client"` file imports `env.ts` or `proxy.ts`.

## Keyboard-only walkthrough of `/`
1. Tab once: "Skip to content" appears; Enter jumps to the main content.
2. Tab to "Load sample", press Enter. The status line announces the sample.
3. Tab to "Block details", press Enter to open it; Tab through the fields, arrow keys for the date-order radios.
4. Tab to "Validate", press Space. Tiles appear (Room nights 9, Errors 0) and the status line announces the result.
5. Tab to the "Errors" filter, press Space: it is marked pressed.
6. Tab to "Format", type "Maestro"; Tab to "Building code", type `MAIN`.
7. Tab to "Download", press Enter. The status line names the file.

Focus is visible throughout. `e2e/keyboard.spec.ts` runs these steps with key presses only.
