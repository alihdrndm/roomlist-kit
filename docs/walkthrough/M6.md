# M6 walkthrough: the HTTP API

## What was built
`apps/api` is a stateless NestJS server around the core library. Four endpoints: `POST /v1/rooming-lists/validate`, `.../convert` and `.../diff` take a multipart upload, and `GET /v1/formats` lists the export targets. `validate` always answers 200 with a report, even for a bad list, because the report is the product. `convert` and `diff` refuse a list with errors (422 `LIST_INVALID`) and return the issues. Every error, from every cause, comes out as one documented `application/problem+json` body whose `instance` is the request id. Uploaded files live in memory for one request and are never stored or logged.

## Design decisions
1. **One place builds every error.** Controllers and services throw an `ApiError` with a code from one table; the global `ProblemFilter` turns anything it recognises into the documented body, and anything it does not recognise into a plain 500 with no internals. `docs/ERRORS.md` has an anchor per code, and a test fails if the table and the doc disagree.
2. **The key is checked before the upload is read.** `ApiKeyGuard` runs ahead of the file interceptor, so an unauthenticated request never costs memory. Keys are compared as SHA-256 hashes with `timingSafeEqual`, so neither the content nor the length of the real key leaks.
3. **Logs cannot hold guest data by construction.** The access-log serializer writes only a fixed list of fields (id, method, path without the query string, user agent, status). A test uploads a list with a known surname and asserts that no log line contains it.

## Delegation and review
Delegated to `routine-builder`: the Swagger documentation and the main e2e suite (96 tests now). Reviewer, first run: 2 BLOCKER, 9 SHOULD-FIX, 7 NOTE. Both blockers were unbounded work from one 5 MB upload (a sparse Excel sheet, and a very wide row giving millions of warnings), fixed in core with bounded reads, a zip-directory check and a cap on warnings. Second run: 3 BLOCKER, 4 SHOULD-FIX. One was a regression of mine (blank Excel headers), fixed. Two remain open for the owner: very large honest workbooks, and short CSV rows that parse slowly. See `docs/DECISIONS.md`, "Open after the M6 reviews".
