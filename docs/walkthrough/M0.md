# M0 walkthrough: workspace scaffold

## What was built
An empty but fully wired monorepo. There are two libraries (`packages/core`, `packages/cli`), a NestJS API (`apps/api`) and a Next.js web app (`apps/web`). Each has one trivial test or page. Every root script works: `pnpm lint`, `typecheck`, `test`, `test:e2e`, `build`, `dev` and `verify`. The API answers `GET /healthz` with `{"status":"ok"}` and `GET /readyz` with 200. A GitHub Actions workflow runs the same checks in CI.

## Design decisions
1. **One toolchain for the whole repo.** Biome does lint and format from one `biome.json`. A shared `tsconfig.base.json` holds the strict TypeScript flags. Each workspace extends it, so later code is held to the same rules.
2. **Config is read in exactly one place per app.** `apps/api/src/config.ts` and `apps/web/src/env.ts` parse environment variables with Zod. In the API a bad value stops the process at boot. The web `env.ts` is not wired into startup yet, so it is only checked once a server file imports it (M7). No other file touches `process.env`.
3. **Generated scaffolds were trimmed, not trusted.** The NestJS and Next.js generators added Jest-style test names, oxlint, prettier, a deploy script and a dark theme. I removed or renamed these to match the spec. Each change is in `docs/DECISIONS.md`.
