# M5 walkthrough: the `roomlist` command-line tool

## What was built
`packages/cli` is a thin command-line wrapper around the core library. `roomlist validate` prints the issues table and the summary. `roomlist convert` writes the hotel file. `roomlist diff` compares two versions of a list. `roomlist formats` shows every export target and what is verified or assumed about it. Every command has a `--json` mode for scripts. The exit code tells a script what happened: 0 means all good, 1 means the list has errors (or the hotel format's requirements are not met), 2 means the command itself was wrong (a missing file, a file over 5 MB, a bad option, or an output file that already exists without `--force`).

## Design decisions
1. **The CLI adds no rules of its own.** Every command parses with `parseRoomingList`, validates with `validateRoomingList` and exports with `exportRoomingList`. `loadList` in `commands/validate.ts` merges the parser's cell issues with the validator's rule issues, so `validate` and `convert` refuse exactly the same lists.
2. **Tests run the real, built program.** `cli.e2e.test.ts` starts `node dist/index.js` with `execa` and checks the exit code, stdout and stderr, as a user or CI script would see them. The test script builds core and the CLI first.
3. **The workspace typechecks from source.** Core's `package.json` has a `@alihdrndm/source` export condition pointing at `src/index.ts`, which the CLI's typecheck uses. A fresh clone can run `pnpm typecheck` before anything is built; the real build still uses core's compiled output.
